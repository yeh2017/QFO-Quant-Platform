# 更新到新版本，如何复制并迁移原有数据

升级 QFO 时，不需要重新拉取全部历史数据。可以把旧版本中的本地数据库复制到新版本，继续使用原有行情、财务、ETF、可转债和同步水位数据。

> **核心原则：**旧版和新版 QFO 必须先完全停止运行，数据库文件必须在新版后端首次启动前复制到位。

## 操作步骤

1. 关闭旧版和新版 QFO 的所有窗口，确认 Python、Node.js 和 QFO 后端均已停止。
2. 下载并完整解压最新稳定版。不要覆盖旧版本文件夹，建议为新版本使用独立目录。
3. 在旧版本中找到数据库：

   ```text
   backend/quant_data.db
   ```

4. 如果新版本的 `backend/` 目录已经存在同名数据库，先备份，不要直接覆盖唯一副本。
5. 将旧版本的 `quant_data.db` 复制到新版本的 `backend/` 目录，最终路径应为：

   ```text
   backend/quant_data.db
   ```

6. 根据新版本目录的状态选择启动方式：

   - 新下载、尚未安装依赖：运行 `run_first_time.bat`。
   - 已经完成依赖安装：运行 `run_quick_start.bat`。

7. 启动后进入数据中台，检查最新日期、数据量和同步水位是否符合预期，再执行日常增量同步。

## 如果存在 WAL 文件

正常关闭 QFO 后，通常只需复制 `quant_data.db`。如果关闭后仍然存在以下文件：

```text
backend/quant_data.db-wal
backend/quant_data.db-shm
```

不要在数据库仍在写入时复制，也不要只复制其中一个文件。先确认所有 QFO、Python 和 Node.js 进程已停止，再将数据库相关文件作为同一组处理。`quant_data.db-wal` 可能包含尚未写回主数据库的数据，`quant_data.db-shm` 通常可由 SQLite 重新生成。

## 注意事项

- 建议迁移到相同版本或更新的稳定版本，不要把新版本数据库复制回旧版本程序。
- 数据库不包含 Tushare Token、API Key 等本地配置，迁移后可能需要重新填写。
- 不要删除旧版本目录，确认新版本运行和数据检查正常后再自行归档。
- 数据迁移前保留一份 `quant_data.db` 备份，出现异常时可恢复。
